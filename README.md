# 小米电视遥控（飞牛 FnOS 应用）

用 ADB 控制同一局域网内的小米电视。手机浏览器打开就是遥控器，
不用再找实体遥控器。

## 功能

- **遥控按键**：电源、音量加减、静音、换台、上下左右、确认、返回、主页、菜单、信号源
- **电视画面**：遥控页顶部显示电视当前画面截图，每 2 秒自动刷新一张；点画面立即手动刷新；可暂停自动刷新。截图经 ADB 取（不是实时视频，画面是静态帧）
- **局域网唤醒开机**：填好电视 MAC 地址，点“开机”先发 WoL 幻数据包再连 ADB
- **发现电视**：扫描本机所在网段的 ADB 端口（5555），列出响应的设备一键填入 IP
- **PWA**：手机浏览器“添加到主屏幕”后全屏打开，像原生遥控器一样
- **账号密码**：默认 admin/admin，设置页可改；忘密码删数据目录 `config.json` 的 `auth` 段，重启恢复默认

## 准备工作（电视上，只做一次）

1. 电视上：**设置 → 关于本机 → 连点“产品型号”（或“版本号”）5–7 下**，提示“已进入开发者模式”。
2. 回到设置 → **账号与安全 → ADB 调试 → 设为允许**（部分固件在“设置 → 通用设置 → 开发者选项”里）。
3. 装好应用后，在设置页填电视 IP，点“测试连接”：电视上会弹出 **“允许 USB 调试？”** 的框，点“允许”（可勾“始终允许这台计算机”），再点一次测试连接，应显示“已连接”。

> 如果电视没有开发者选项、或开不了 ADB 调试，本应用无法使用（电视厂商锁死了这条路）。
> 局域网唤醒只在电视待机不断电、且支持网络唤醒时有效；彻底断电关机后唤不醒。

## 电视重启后 ADB 被复位（小米固件，重要）

部分小米电视（实测系统版本 1.3.130）**用遥控器开机后，ADB 开关会被复位成“拒绝”**——不只是彻底断电/重启才复位，待机唤醒也可能复位。这是小米固件的行为，不是本应用的 bug。

- 症状：之前遥控得好好的，电视用遥控器开机后，点“测试连接”就报“连接被拒”。
- 解决：电视上重新开一次 ADB 调试（设置 → 账号与安全 → ADB 调试 → 允许），再点“测试连接”；如果弹出“允许 USB 调试？”的框，再点一次“允许”。
- 区分：遥控器电源键是待机（不断电），一般不复位；但这台固件连待机唤醒都可能复位。彻底断电、拔电源、系统重启后，ADB 开关基本都会被复位，需要重新开。

## 安装

飞牛应用中心安装前，需先装好 **Python** 工具（应用中心搜 Python）。
应用默认端口 **18091**，装好后打开 `http://NAS-IP:18091`，默认账号密码 `admin/admin`。

电视 IP 怎么看：电视 → 设置 → 网络 → 查看；或用设置页的“发现电视”扫描。
电视 MAC 怎么看：电视 → 设置 → 关于本机 → 状态信息；或路由器后台查。

## 技术说明

- 不依赖 NAS 上装 adb：纯 Python 的 adb-shell（0.4.4）+ rsa（4.9.1）+ pyasn1（0.6.5）全部 vendored 在 `app/vendor/` 里（均为 Apache-2.0 / BSD 协议），直接连电视的 5555 端口发 `input keyevent`。
- 首次连接时应用在数据目录生成一对 RSA 密钥（`adbkey` / `adbkey.pub`，持久保存），连接时把公钥发给电视；用户在电视上点“允许”后，密钥即被电视记住。
- 连接状态明确区分：已连接 / 连接被拒（ADB 没开）/ 等待电视上点允许 / 超时。
- 服务只监听局域网端口，不向公网映射、不外发数据。

## 已知限制

- **已在真电视上实测过（2026-11-13，小米电视系统版本 1.3.130）**：1.0.2 实测发现三个问题，1.0.3 已修——①按键约 2 秒才有反应：截图失败会把共用 ADB 连接丢掉，下一键又要重新握手；现按键与截图各用一条持久连接，截图再慢也不挡按键。②电视画面加载不出来：这台电视上单次 ADB 命令本身就慢，`exec-out screencap` 超时；现截图改三方法兜底（exec-out → base64 → 落文件再读），超时放宽到 25 秒，失败给具体原因。③用遥控器开机后 ADB 测试自动跳“拒绝”：小米固件行为（见上节），重新开一次 ADB 调试即可。WoL 真实广播因沙箱禁 UDP 未实测，仍待真机确认。
- 电视画面是每 2 秒一张的静态截图，不是实时视频；截图一次约 0.5–1 秒（慢电视上更久），刷新时若上一张还没回来会自动跳过。
- 有些小米电视型号的 ADB 在待机时会被系统杀掉，唤醒后需等几秒再连。
